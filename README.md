# Handflow

Handflow 是一款 Windows 多模型工作台。你可以用单个模型聊天，也可以在画布上安排多个模型分工，让它们按连线交接结果。它适合软件开发、资料整理、内容撰写等需要分阶段完成的任务。Handflow 不自带模型或 API Key，需要接入自己的模型服务。

## 下载与安装

1. 打开 [Windows x64 预览版 v1.0.0-preview.1](https://github.com/GJYGitHub/handflow-releases/releases/tag/v1.0.0-preview.1)，在 **Assets** 中下载 `HandflowSetup.exe`。不要下载 `Source code` 压缩包；这个仓库用于分发安装包，不包含应用源码。
2. 在 Windows 10 或 11 的 x64 电脑上运行安装包，按向导完成安装。无需安装 Flutter、Visual Studio 或 Inno Setup。默认安装位置是 `%LOCALAPPDATA%\Programs\Handflow`，安装后可从开始菜单打开。
3. 此预览版**未签名**，Windows 可能提示未知发布者或拦截。请只从本仓库下载；有疑虑时可核对发布页提供的 SHA-256，不要关闭系统安全保护。哈希只能核对文件是否一致，不能替代代码签名。

此版不提供应用内自动更新。后续版本请到 [Releases](https://github.com/GJYGitHub/handflow-releases/releases) 查看并手动安装。

## 首次使用：接入模型

1. 点击左上角「配置教程」→「下载 TXT 模板」，用文本编辑器打开模板。
2. 按服务商提供的信息填写以下字段，并将文件保存为 UTF-8 文本。示例只是占位，不是可用账号。

   ```ini
   [model_1]
   name = 我的聊天模型
   provider = openai_compatible
   base_url = https://example.com/v1
   model = actual-model-id
   api_key = YOUR_API_KEY
   ```

   - `name` 是工作台中显示的名称，不能重复；`model` 是服务商提供的实际模型 ID。
   - `provider` 使用 `openai_compatible` 或 `anthropic`。`base_url` 填 API 基础地址，不附加 `/chat/completions`、`/messages` 或 `/images/generations`。远程地址使用 HTTPS；本机回环接口可使用 HTTP。
   - 每个模型单独写一个节，例如 `[model_2]`。同一个 Key 有权访问多个模型时可以填入多个节。工作台不会根据 Key 自动枚举模型，不要在一个 `model` 字段中填写多个 ID。
3. 打开「设置」→「浏览」，选择 TXT 文件。可点击「验证主模型连接」发起一条测试请求；服务商可能计费。
4. 新建聊天，在输入区选择模型，发送一条短消息。重启时工作台会尝试从原路径重新读取配置；文件移动或修改模型、协议、地址后，请重新选取。

**密钥请保存在项目目录之外。** TXT 是明文文件，不要上传、截图分享或粘贴到聊天。请求时，密钥会用于向你配置的服务商认证。

## 聊天与项目

- **普通聊天**：不需要关联项目。选择模型和推理强度后即可发送文字，也可用附件按钮添加图片或 UTF-8 文本。阅读图片需要所选模型和接口都支持视觉输入。
- **项目聊天**：点击侧栏「项目」旁的「+」选择本地文件夹。关联后，模型可按权限请求读取或修改项目文件，以及在允许的场景下运行命令。将鼠标移到输入区的项目名上，点关闭按钮可解除关联。侧栏移除项目不会删除磁盘文件。
- **权限**：建议先用「只读」，确需改文件时再选择需要确认的权限。谨慎使用「完全访问」：命令和 MCP 服务不是系统沙箱，可能访问项目外文件或联网。只批准理解且信任的操作。
- **多任务**：发送后可以打开另一个聊天或工作流，原任务继续运行。当前最多同时运行 2 条任务，超出则排队；待确认的任务仍占用位置。完全退出应用后任务不会继续运行。

## 编排工作流

1. 点击顶部「工作流」，在空白画布上右键添加「需求节点」和「工作节点」。填写需求，为每个工作节点选择模型与职责。
2. 选择模板：
   - **软件开发**：适合「前端与后端并行 → 主模型整合 → 测试」。主模型生成计划后，需要用户确认；需要独立测试时，添加测试节点并选好验证策略。
   - **自由编排**：适合「资料整理 → 撰写 → 审校」。从上游节点右侧圆点连到下游左侧圆点，按依赖执行，不要求配置专门的主模型或测试模型。
3. 按需添加「图片/文件节点」。在「节点输入」里选择附件发送给谁，并为连线选择完整结果、摘要、结构化结果、文件路径或附件。只传下游需要的内容，减少重复发送和 token 消耗。
4. 点击「执行」，在底部「工作记录」查看进度、确认计划或处理审批。失败或中断后，支持恢复的任务会显示「继续执行」；有效的检查点可复用，但已发生的写入和计费不会回滚。
5. 画布草稿会在本机自动保存，也可通过「保存」导出 JSON，再用「导入」载入。导出的文件可能包含需求和附件快照，分享前请检查内容。

**生成图片：** 在「自由编排」中添加「图片生成节点」，选择支持 `/images/generations` 的模型。可选择尺寸和画质，默认使用服务商设置，结果可在工作台预览。聊天兼容接口不一定支持生图，当前图片生成节点不接收参考图。使用本机 ComfyUI 实际渲染是另一条路径，需要提前启动 ComfyUI 并安装相关节点和模型。

## 插件、技能与设置

- 在「插件与技能」从公开 GitHub 仓库安装包含 `SKILL.md` 的技能。可手动指定技能，或由模型按需读取。安装技能不等于安装或连接 MCP 服务。
- 本地 MCP 服务需要单独配置启动命令、参数并确认启动。只连接可信来源；不要把密钥粘贴到聊天或工作流需求中。
- 在「设置」切换跟随系统、浅色或深色主题，选择正常、简洁或极简回复。可按需开启记忆或插件自动翻译；翻译可能额外消耗 token。
- 聊天记录和工作流草稿保存在本机，Windows 默认数据目录是 `%APPDATA%\com.example\qianshou`。提交请求时，相关对话、附件、工具返回或记忆仍可能发送给所选模型服务商。本地记录和备份不是加密的。

## 常见问题

| 问题 | 建议 |
| --- | --- |
| 导入后没有模型，或验证失败 | 检查 TXT 分节、`provider`、`base_url`、模型 ID、Key 权限及服务商额度。推理强度不兼容时先切回默认。 |
| 工作流一直显示待确认 | 打开对应任务，展开底部「工作记录」，检查是否有待确认的计划、审批或失败处理。 |
| 模型说已修改文件，但找不到文件 | 确认关联了正确的项目且有写入权限，再查看工具操作结果。模型的文字回复不等于实际写盘或测试通过。 |
| 想查天气或搜索网页 | 直接在任务中提出，模型可按需调用工具。模型或网关需要支持工具调用，搜索也可能受网络限制。 |
| 无法在应用内升级 | 这是未签名的预览版，请从 GitHub Releases 手动下载后续安装包。 |

遇到问题时，请记录 Handflow 版本、Windows 版本、复现步骤以及已去除密钥、私人路径和聊天内容的错误截图。
